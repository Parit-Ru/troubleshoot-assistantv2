## 3. `Icon.tsx`

### โครงสร้าง

- `IconName` เป็น union ของชื่อ 14 ชื่อ ถ้าพิมพ์ชื่อผิด TypeScript แจ้งตั้งแต่ตอนเขียน ไม่ใช้ `enum` เพราะ `tsconfig` ตั้ง `erasableSyntaxOnly` ซึ่งห้าม `enum`
- `ICONS` เป็นตารางค้นหา ชื่อ → `viewBox` + เส้นที่ประกอบเป็นรูป ชนิดเป็น `Record<IconName, ...>` ถ้าเพิ่มชื่อแล้วลืมเพิ่มรูป TypeScript จะแจ้ง
- ค่าของเส้นทั้งหมด (`stroke="currentColor"` หนา 2 ปลายมน) ตั้งที่ `<svg>` ตัวนอกที่เดียว path ข้างในจึงสั้น

### ทำไมสีมาจาก `currentColor`

ไอคอนรับสีตัวอักษรของตัวที่ครอบอยู่ เขียน `<span className="text-danger"><Icon name="warning" /></span>` ก็ได้ไอคอนสีแดง ไม่ต้องมี prop สี

### ทำไมไม่ใช้ไลบรารีไอคอน

ต้องการแค่ 14 ตัว การติดตั้งไลบรารีเพิ่ม dependency โดยไม่จำเป็น และ path ที่วาดเองอธิบายได้ทุกเส้น

### การเข้าถึง

ปกติไอคอนอยู่คู่กับข้อความ จึงใส่ `aria-hidden` ให้โปรแกรมอ่านหน้าจอข้ามไป ถ้าไอคอนอยู่ลำพังให้ส่ง `label` มา จะกลายเป็น `role="img"` พร้อม `aria-label`

## 4. `Button.tsx`

| แบบ | ใช้กับ |
|---|---|
| `primary` | การกระทำหลักของหน้า พื้นส้ม ตัวอักษร `text-canvas` |
| `secondary` | การกระทำรอง |
| `answer` | ปุ่มตอบคำถามของสถานะแบบ checkpoint กว้างเต็มแถว |
| `text` | ลิงก์เล็กในรูปแบบปุ่ม |

### ทำไมต้องเขียนชื่อคลาสเต็มทุกคำ

Tailwind หาคลาสที่ต้องสร้างโดย**อ่านข้อความในไฟล์ตรงๆ** ไม่ได้รันโค้ด ถ้าเขียน `` `bg-${color}` `` Tailwind มองไม่เห็นคำว่า `bg-accent` และจะไม่สร้าง CSS ให้ ปุ่มจะไม่มีสีโดยไม่มี error เตือน

การต่อ**ชื่อที่เขียนเต็มแล้ว**เข้าด้วยกัน เช่น `[BASE_CLASSES, VARIANT_CLASSES[variant]].join(' ')` ไม่มีปัญหา เพราะทุกชื่อปรากฏเต็มอยู่ในไฟล์

### ทำไม padding อยู่ในแต่ละแบบ ไม่อยู่ในคลาสพื้นฐาน

ถ้าปุ่มเดียวมีทั้ง `px-4` และ `px-0` ตัวที่ชนะขึ้นกับลำดับใน CSS ที่ Tailwind สร้าง ไม่ใช่ลำดับที่เราเขียน ผลจึงเดาไม่ได้

### รายละเอียดอื่น

- `type="button"` เป็นค่าเริ่มต้น เพราะค่าปกติของ HTML คือ `submit` ซึ่งจะส่งฟอร์มโดยไม่ตั้งใจ
- `isLoading` ทำให้ปุ่มกดไม่ได้และแสดงตัวหมุน กันการกดเบิ้ลฝั่งหน้าเว็บ (การกันฝั่งเซิร์ฟเวอร์เป็นเรื่องแยก — B4)
- ใช้ `enabled:hover:` ปุ่มที่ปิดอยู่จึงไม่เปลี่ยนสีเมื่อเอาเมาส์ชี้

## 5. `Notice.tsx`

| สี | ใช้กับ |
|---|---|
| `info` | ข้อมูลทั่วไป |
| `success` | แก้ปัญหาได้แล้ว (สถานะสิ้นสุดแบบ resolution) |
| `accent` | ส่งต่อศูนย์บริการ (สถานะสิ้นสุดแบบ escalation) |
| `danger` | คำเตือนความปลอดภัยของสถานะที่เป็น safety_critical |

- พื้นใช้ความทึบ 10% (`bg-danger/10`) ขอบ 40% ตัวเนื้อความเป็น `text-ink` ทุกสี สีประจำกล่องใช้เฉพาะไอคอนและหัวข้อ เพื่อให้อ่านง่ายบนพื้นมืด
- `children` รับอะไรก็ได้ ด่านความปลอดภัยจึงวางช่องติ๊กไว้ในกล่องแดงได้ ตัวกล่องเองไม่มีตรรกะของด่าน
- **ตั้งใจไม่ใส่ `role="alert"`** เพราะกล่องทุกใบจะถูกอ่านออกเสียงทันทีที่แสดง รวมถึงข้อความทั่วไป จะตัดสินใจเฉพาะกล่องคำเตือนความปลอดภัยตอนทำหน้าตรวจอาการ

## 6. `ServerStatus.tsx`

| แบบ | เงื่อนไข | ข้อความ |
|---|---|---|
| `mock` | `VITE_USE_MOCK=true` | โหมดจำลอง |
| `checking` | รอ `/health` ตอบ | กำลังเชื่อมต่อเซิร์ฟเวอร์ |
| `ok` | ตอบ `status: 'ok'` | เซิร์ฟเวอร์พร้อมใช้งาน |
| `degraded` | ตอบ `status: 'degraded'` | ฐานข้อมูลของเซิร์ฟเวอร์มีปัญหา |
| `offline` | เรียกไม่สำเร็จ | เชื่อมต่อเซิร์ฟเวอร์ไม่ได้ |

### ทำไมต้องเช็คโหมดจำลองก่อนอย่างอื่น

ในโหมดจำลอง `useHealth()` ตั้ง `enabled: false` ไว้ query ที่ปิดอยู่จะ**ค้างสถานะ `pending` ตลอดไป** ถ้าเช็ค `isPending` ก่อน ป้ายจะขึ้น "กำลังเชื่อมต่อ" ไม่มีวันจบ

### ทำไมเรียก `useHealth()` ก่อน `if`

กฎของ React ห้ามเรียก hook แบบมีเงื่อนไข ลำดับการเรียก hook ต้องเหมือนกันทุกครั้งที่วาด เรียกไว้ก่อนแล้วค่อยตัดสินใจจากผลจึงปลอดภัย

### รายละเอียดอื่น

- `role="status"` ให้โปรแกรมอ่านหน้าจออ่านเมื่อสถานะเปลี่ยน โดยไม่ขัดสิ่งที่กำลังอ่านอยู่
- `title` แสดงข้อความ error จริงเมื่อเอาเมาส์ชี้ ช่วยตอนหาบั๊ก เช่นลืมตั้ง `VITE_API_URL`

## 7. `AppShell.tsx`

### markup ชุดเดียวทั้งมือถือและจอใหญ่

ใช้คลาส `md:` (กว้างตั้งแต่ 768px) เปลี่ยนรูปร่าง แทนการเขียนเมนูสองชุดแล้วซ่อนชุดหนึ่ง

| | มือถือ | จอใหญ่ |
|---|---|---|
| แถบนำทาง | แถบแนวนอนด้านบน | sidebar ซ้าย สูงเต็มจอ ติดอยู่กับที่เมื่อเลื่อนหน้า |
| ป้ายสถานะ | บรรทัดใหม่ใต้เมนู | ล่างสุดของ sidebar (`md:mt-auto`) |

เมนูมีที่เดียว แก้ที่เดียว

### ทำไมแถบโหมดจำลองไม่อยู่บนสุดของทั้งหน้า

รอบแรกวางไว้เหนือทุกอย่าง ตอนทดสอบพบว่า sidebar ที่สูงเท่าจอ (`h-screen`) ถูกดันลงไปเท่าความสูงของแถบ ป้ายสถานะท้าย sidebar จึงล้นออกนอกจอ จึงย้ายแถบไปอยู่บนสุดของคอลัมน์เนื้อหาแทน

### `NavLink` กับ `end`

`NavLink` ใส่ `aria-current="page"` ให้เมนูที่ตรงกับ URL อยู่แล้ว แต่ต้องใส่ `end` เพราะทุก path ขึ้นต้นด้วย `/` ถ้าไม่ใส่ เมนู "หน้าแรก" จะถูกนับว่าเลือกอยู่ในทุกหน้า

### ชื่อแอปเก็บไว้ที่เดียว

`APP_NAME` อยู่บนสุดของไฟล์ เพราะชื่อ FixBot ซ้ำกับผลิตภัณฑ์ของ iFixit และรอเปลี่ยน ตอนเปลี่ยนแก้บรรทัดนี้กับ `<title>` ใน `index.html`

## 8. หน้าทั้ง 5 หน้า

| หน้า | route | สถานะ |
|---|---|---|
| `HomePage` | `/` | ชั่วคราว |
| `SymptomsPage` | `/symptoms` | ชั่วคราว |
| `SessionPage` | `/session/:sessionId` | ชั่วคราว — แสดงค่า `sessionId` ที่อ่านจาก URL ด้วย `useParams()` |
| `NodeGalleryPage` | `/gallery` | ชั่วคราว — ไม่อยู่ในเมนู |
| `NotFoundPage` | `*` | ตัวจริง |

### ทำไมหน้าชั่วคราวยังไม่ดึงข้อมูล

ขั้นนี้มีหน้าที่แค่วางโครง ถ้าใส่การดึงข้อมูลตอนนี้ ขั้นที่ทำหน้าจริงต้องเขียนใหม่อยู่ดี และถ้ามีบั๊กจะแยกไม่ออกว่ามาจากโครงแอปหรือจากการดึงข้อมูล

### ลิงก์ใช้ `Link` ไม่ใช้ `Button`

การพาไปหน้าอื่นเป็นลิงก์ ไม่ใช่การกระทำ ถ้าใช้ `<button>` โปรแกรมอ่านหน้าจอจะบอกประเภทผิด และคลิกขวาเปิดในแท็บใหม่ไม่ได้

### `NotFoundPage` ไม่ใช่หน้าสำหรับ session ที่หาไม่เจอ

URL ที่ไม่มีอยู่ (เช่น `/sympotms`) → `NotFoundPage`
URL ถูกแต่เซิร์ฟเวอร์ตอบ `SESSION_NOT_FOUND` (เช่น session หมดอายุ) → `SessionPage` ต้องจัดการเอง

URL ที่ผิดจะแสดงให้ผู้ใช้เห็น และใช้ `break-all` ให้ URL ยาวที่ไม่มีช่องว่างตัดบรรทัดได้บนมือถือ

## 11. ตรวจสอบอย่างไร

ขั้นนี้เป็นชิ้นส่วนหน้าจอ ไม่ใช่ตรรกะล้วน จึงไม่ได้เขียนเทสก่อน และ**ไม่มีเทส component ที่ commit เข้า repo** (ต้องติดตั้ง Testing Library เพิ่ม เก็บไว้ในงานเสริม)

ทุกไฟล์ผ่านการตรวจเหล่านี้ก่อนส่ง:

- `tsc -b`, `eslint` และ `vite build` ผ่าน
- render จริงใน Chromium แบบ headless แล้วดูภาพหน้าจอ
- `ServerStatus` ทดสอบครบ 5 แบบ โดยดัก request ไป `/health` แล้วแกล้งให้ตอบ ok, degraded, ล้มเหลว และไม่ตอบเลย
- build โหมดจำลองยิง `/health` **0 ครั้ง**
- `AppShell` ทดสอบที่ความกว้าง 1280px และ 375px ไม่มีการเลื่อนแนวนอน ป้ายสถานะไม่ล้นจอ
- เปิดครบ 5 route, กด F5 แล้วยังอยู่หน้าเดิม, console ไม่มี error
- build จริง (`VITE_USE_MOCK=false`) ยังไม่มีข้อมูลจำลองหลุดเข้าไป

`App.tsx` ที่ใช้ทดสอบแต่ละขั้น revert ทุกครั้ง

## 13. คำถามที่กรรมการอาจถาม

**"ทำไมใช้ URL แบบมี # ดูไม่สวย"**

> เพราะ deploy บน GitHub Pages ครับ ซึ่งตั้งค่าเซิร์ฟเวอร์ไม่ได้ ถ้าใช้ URL ปกติ ผู้ใช้กด F5 ในหน้าตรวจอาการจะได้ 404 ส่วนหลัง # ไม่ถูกส่งไปเซิร์ฟเวอร์ GitHub จึงส่งหน้าแอปให้เสมอ แล้วแอปอ่านส่วนนั้นเอง

**"ปุ่มปิดตัวเองตอนรอ แปลว่าด่านความปลอดภัยอยู่ที่หน้าเว็บหรือเปล่า"**

> ไม่ใช่ครับ การปิดปุ่มแค่กันผู้ใช้กดเบิ้ลโดยไม่ตั้งใจ ด่านความปลอดภัยจริงอยู่ในฟังก์ชันเปลี่ยนสถานะของกลไกควบคุมเครื่องสถานะ ต่อให้แก้โค้ดหน้าเว็บให้ข้ามการติ๊กยืนยัน คำสั่งก็จะถูกปฏิเสธและสถานะไม่ขยับ ตอนนี้ยืนยันด้วยเทสของกลไกควบคุม ส่วนการสาธิตผ่าน HTTP ต้องรอ REST API

**"ทำไมไม่ใช้ไลบรารี UI สำเร็จรูป"**

> ชิ้นส่วนที่ต้องใช้มีแค่ปุ่ม กล่องข้อความ และไอคอนครับ เขียนเองได้ในไม่กี่สิบบรรทัดต่อไฟล์ และอธิบายได้ทุกบรรทัด ถ้าใช้ไลบรารีจะได้โค้ดที่อธิบายกลไกข้างในไม่ได้ และเพิ่ม dependency ที่ต้องดูแล

**"หน้าจอเกือบทั้งหมดยังเป็นหน้าชั่วคราว ขั้นนี้ได้อะไร"**

> ได้โครงที่ทุกหน้าใช้ร่วมกันครับ คือการเปลี่ยนหน้า แถบนำทางที่ใช้ได้ทั้งมือถือและจอใหญ่ ป้ายสถานะเซิร์ฟเวอร์ และชิ้นส่วนพื้นฐาน 3 ชิ้น ตรวจแยกจากการดึงข้อมูลแล้ว พอทำหน้าจริง ถ้ามีบั๊กจะรู้ทันทีว่าอยู่ที่ตัวหน้า ไม่ใช่ที่โครง
