# frontend/.env.production

> หมายเหตุ: สรุปนี้แสดง **เฉพาะชื่อตัวแปรและคอมเมนต์** ไม่ได้เปิดดูหรือคัดลอกค่าของตัวแปร

## 1. หน้าที่ของไฟล์

ตัวแปรสภาพแวดล้อมที่ Vite ใช้ตอน `npm run build` และ `npm run deploy` (โหมด production) กำหนดที่อยู่ backend บน Render และบังคับไม่ใช้เซิร์ฟเวอร์จำลอง ไฟล์นี้ commit ขึ้น git ได้ ไม่มีความลับ

- **ใครเรียกใช้**: Vite ตอน build ; โค้ดอ่านผ่าน `import.meta.env.VITE_*` เช่นเดียวกับ `.env.development`
- **เรียกใช้**: ไม่มี

## 2. อธิบายทีละบล็อก

| บรรทัด | ตัวแปร | ความหมายตามคอมเมนต์ |
|---|---|---|
| 7 | `VITE_API_URL` | ที่อยู่ backend บน Render (ดูได้จาก Dashboard ของ service) — ห้ามใส่ `/` ท้าย และ **ต้องเป็น https ไม่ใช่ http** |
| 10 | `VITE_USE_MOCK` | **ต้องเป็น `false` เสมอ** — เว็บจริงห้ามใช้เซิร์ฟเวอร์จำลอง |

## 3. การส่งข้อมูล

```
.env.production ─Vite build─► ค่าถูกฝังเป็นข้อความคงที่ในไฟล์ JS ใน dist/ ─► deploy ขึ้น GitHub Pages (npm run deploy)
```
หน้าเว็บที่ deploy จะเรียก backend ตามที่อยู่ที่ฝังไว้ และ backend ต้องตั้ง `CORS_ORIGIN` ให้ตรงกับ origin ของหน้าเว็บ (ดู `backend/scripts/check-deployed-search.js` ที่ตรวจเรื่องนี้)

## 4. จุดที่ควรระวัง

- ค่าถูกฝังตอน build: ถ้าที่อยู่ backend เปลี่ยนต้อง build + deploy ใหม่
- ถ้า `VITE_USE_MOCK` ถูกตั้งผิดเป็น true ผู้ใช้จริงจะได้ข้อมูลจากเซิร์ฟเวอร์จำลองในเบราว์เซอร์โดยไม่เรียก backend (ซึ่งรวมถึงด่านความปลอดภัยฝั่งเซิร์ฟเวอร์ด้วย) — คอมเมนต์จึงย้ำให้เป็น false เสมอ
- ต้องเป็น https มิฉะนั้นเบราว์เซอร์บล็อกการเรียก http จากหน้าที่เสิร์ฟด้วย https (mixed content) (อนุมานจากพฤติกรรมของเบราว์เซอร์)
