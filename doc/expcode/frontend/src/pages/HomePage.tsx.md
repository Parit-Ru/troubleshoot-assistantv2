# frontend/src/pages/HomePage.tsx

## 1. หน้าที่ของไฟล์

หน้าแรก (route `/`) : บอกด้วยภาษาผู้ใช้ทั่วไปว่าระบบทำอะไรและต่างจากการถาม AI ตรงไหน (ไม่ใช้ศัพท์เทคนิค ไม่ใส่ตัวเลขสถิติเพราะไม่มีข้อมูลจริงรองรับ) มี 3 ส่วน : (1) ข้อความแนะนำ + ปุ่ม "เลือกอาการที่พบ" (2) "รองรับตอนนี้" ดึงจากข้อมูลจริง (`useGraphs`) ไม่พิมพ์ตายตัว (3) ภาพตัวอย่างเส้นทางการตรวจ เป็นภาพนิ่ง กดอะไรไม่ได้

- **ใครเรียกใช้**: `App.tsx` (route `/`)
- **เรียกใช้**: `useGraphs` (`api/queries`), `PathRail`, `Button`, `Icon`, `Notice`, `DEVICE_CATEGORY_LABELS`/`STEP_KIND_LABELS` (`lib/labels`), `formatSourceLine`, `groupSymptoms`, `toTrailEntry`, `checkpointNode`/`safetyGateNode` (`mocks/fixtures`), `useNavigate`

## 2. อธิบายทีละบล็อก

### บล็อก A — ข้อมูลภาพตัวอย่าง (บรรทัด 27–60)
- `POWER_CHECKPOINT` (42–46): สร้างจาก `checkpointNode` เปลี่ยนเป็น `nodeId: 'n1'` กับข้อความ "เครื่องได้รับไฟฟ้าอยู่หรือไม่? (ตรวจปลั๊ก/เต้ารับ)" (คัดลอกจาก `samsung_ac_ar70h.json` ตรงๆ; ที่มาหน้า 43 เหมือน n2)
- `SAMPLE_TRAIL` (53–56): สองขั้นที่ผ่านมา (n1 → ตอบ ใช่, n2 → ตอบ ใช่) สร้างด้วย `toTrailEntry` ตัวเดียวกับหน้าตรวจจริง คำนวณครั้งเดียวนอกฟังก์ชัน ; ขั้นปัจจุบันคือ `safetyGateNode` (`n_fix_breaker`) — เป็นเส้นทางจริงของอาการ "แอร์ไม่ทำงาน เปิดไม่ติด"
- `SAMPLE_SYMPTOM_NAME`, `SAMPLE_MANUAL_LABEL` (59–60): ค่าตายตัว (`'แอร์ไม่ทำงาน เปิดไม่ติด'`, `'Samsung AR70H**D1***'`)

### บล็อก B — `HomePage()` (บรรทัด 66–165)
- `graphs = useGraphs()`; `groups = graphs.isSuccess ? groupSymptoms(graphs.data) : []`; `showSupported = graphs.isPending || groups.length > 0` — โหลดไม่สำเร็จหรือไม่มีข้อมูลซ่อนทั้งส่วน ไม่ขึ้นกล่องแดง เพราะหน้าแรกยังใช้ได้และหน้าเลือกอาการแจ้ง error เอง
- เลย์เอาต์ `grid` : จอเล็กเรียงข้อความ → ภาพตัวอย่าง → รองรับตอนนี้ ; จอ `lg` สองคอลัมน์ (ข้อความและ "รองรับตอนนี้" ซ้อนกันทางซ้าย ภาพตัวอย่างอยู่ขวาสูงสองแถว) ลำดับ HTML จึงไม่ตรงตำแหน่งบนจอใหญ่ ต้องระบุตำแหน่งเอง
- ส่วนที่ 1 (87–101): `<h1>` "ตรวจอาการทีละขั้น / ตามคู่มือของผู้ผลิต" + ย่อหน้าอธิบาย (ลำดับมาจากคู่มือ ไม่ให้ AI เดา; ขั้นตอนเกี่ยวกับไฟฟ้าต้องยืนยันคำเตือนทุกครั้ง; ทุกขั้นบอกหน้าคู่มือ) + `Button` ไป `/symptoms`
- ส่วนภาพตัวอย่าง (104–136): `<figure>` ใช้ `PathRail` จริง แต่กล่องขั้นตอนเขียนเป็นกล่องอ่านอย่างเดียวขึ้นมาเอง (ไม่ใช้ `StepView`/`StepCard` เพราะ `StepView` มีปุ่มกดได้ที่กดแล้วไม่เกิดอะไร และ `StepCard` มีปุ่ม "ดูรหัสเอกสาร" ในภาพที่ควรนิ่ง) หน้าตาเหมือน `StepCard tone="danger"`
- ส่วน "รองรับตอนนี้" (139–162): วนกลุ่มแสดง "<ประเภทเครื่องเป็นไทย> <ยี่ห้อ> <รุ่น>" และจำนวนอาการ

## 3. การส่งข้อมูล

`GET /traversal/graphs` → `useGraphs` → `groupSymptoms` → รายการ "รองรับตอนนี้" ; ภาพตัวอย่างใช้ข้อมูลคงที่จาก `fixtures.ts` + `toTrailEntry`

## 4. จุดที่ควรระวัง

- **ภาพตัวอย่างพึ่งข้อความที่คัดลอกจากไฟล์ผังแอร์ด้วยมือ** ถ้าแก้ผังแล้วตัวอย่างไม่ตามอัตโนมัติ
- หน้าแรกยังพึ่ง `mocks/fixtures.ts` (ไม่ใช่เฉพาะโหมดจำลอง)
- ข้อความ "ขั้นตอนที่เกี่ยวกับไฟฟ้าต้องยืนยันคำเตือนก่อนทุกครั้ง" เป็นคำกล่าวของหน้าเว็บ ซึ่งสอดคล้องกับ 3 โหนด safety ในข้อมูลแอร์ปัจจุบัน
