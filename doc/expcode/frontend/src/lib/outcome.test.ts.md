# frontend/src/lib/outcome.test.ts

## 1. หน้าที่ของไฟล์

ไฟล์ทดสอบ (Vitest) ของ `outcome.ts` : `normalizeOutcome`, `checkOutcome`, `formatOutcomeCounter`

- **ใครเรียกใช้**: Vitest ; **เรียกใช้**: `MAX_OUTCOME_LENGTH`, `checkOutcome`, `formatOutcomeCounter`, `normalizeOutcome` จาก `./outcome`

## 2. อธิบายทีละบล็อก (9 เทส)

| กลุ่ม / บรรทัด | สิ่งที่ยืนยัน |
|---|---|
| `normalizeOutcome` (9–13) | ตัดช่องว่างหน้าหลัง แต่ไม่แตะช่องว่าง/ขึ้นบรรทัดใหม่กลางข้อความ |
| `checkOutcome` (15–42) | ข้อความปกติ → `ok` ; ว่าง/ช่องว่าง/แท็บ/ขึ้นบรรทัด → `empty` ; ยาวพอดี 1000 → `ok`, เกิน 1 → `too-long` ; นับหลังตัดช่องว่าง ; **`MAX_OUTCOME_LENGTH` ต้องเป็น 1000** (เทสเตือนเมื่อ backend เปลี่ยน) ; ข้อความที่ดูเหมือน `<script>` ผ่านเหมือนข้อความอื่น (ไม่ตรวจเนื้อหา) |
| `formatOutcomeCounter` (44–53) | `''` → `0/1000`, `'แอร์เย็นแล้ว'` → `12/1000` ; นับรวมช่องว่าง (`'  ก  '` → `5/1000`) |

## 3. การส่งข้อมูล

Vitest เรียกฟังก์ชันล้วนโดยตรง ไม่มี DOM/HTTP

## 4. จุดที่ควรระวัง

- เทส "เพดาน = 1000" เป็นเพียงการล็อกค่าฝั่ง frontend — ไม่ได้เทียบกับ backend จริง
- ไม่มีเทสอักขระนอก BMP (อีโมจิ) ที่นับเป็น 2
