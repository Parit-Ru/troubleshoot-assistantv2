# frontend/src/lib/trail.test.ts

## 1. หน้าที่ของไฟล์

ไฟล์ทดสอบ (Vitest) ของ `toTrailEntry` ใช้ตารางกรณีทดสอบ (สถานะที่เพิ่งผ่าน + action → ป้ายและสัญลักษณ์ที่ต้องแสดง) โดยจับคู่สถานะกับ action ให้ตรงกับที่เกิดขึ้นได้จริง (เช่น `confirm_safety` ส่งได้เฉพาะสถานะที่ต้องยืนยันคำเตือน)

- **ใครเรียกใช้**: Vitest
- **เรียกใช้**: `toTrailEntry`/`TrailMarker` (`./trail`), type `RenderedNode`/`TraversalAction`, และข้อมูลตัวอย่างจาก `../mocks/fixtures` (`checkpointNode`, `inputNode`, `instructionNode`, `safetyGateNode`)

## 2. อธิบายทีละบล็อก

- `CASES` (12–54): 5 กรณี — ตอบใช่ที่คำถาม (`ตอบ ใช่`/`dot`), ตอบไม่ใช่ (`ตอบ ไม่ใช่`/`dot`), กดถัดไปที่ขั้นตอนธรรมดา (`ไปต่อแล้ว`/`dot`), ยืนยันคำเตือนที่ขั้นตอนอันตราย (`ยืนยันคำเตือนแล้ว`/`switch-off`), กรอกรหัส `E1` (`กรอก E1`/`dot`)
- `it.each(CASES)` (57–64): ตรวจว่า `toTrailEntry(node, action)` เท่ากับ `{nodeId, text, answerLabel, marker}` ที่คาด
- เทสเพิ่ม (66–70): กรอก `'e1'` (ตัวพิมพ์เล็ก) → ป้ายเป็น `กรอก e1` (ไม่แปลง ไม่ตรวจรูปแบบ ซึ่งเป็นงานของเครื่องสถานะ)

## 3. การส่งข้อมูล

Vitest เรียกฟังก์ชันล้วนด้วยข้อมูลตัวอย่างจาก `fixtures.ts` (ไม่มี HTTP)

## 4. จุดที่ควรระวัง

- เทสนี้พึ่ง `mocks/fixtures.ts` (ไฟล์ข้อมูลตัวอย่างของโหมดจำลอง) — ถ้าตัดโฟลเดอร์ `mocks/` ออกจากโปรเจกต์ ต้องย้าย fixtures มาไว้ที่อื่น
