# frontend/src/lib/symptoms.test.ts

## 1. หน้าที่ของไฟล์

ไฟล์ทดสอบ (Vitest) ของ `symptomName` และ `groupSymptoms` ใช้ชื่ออาการจริง 4 อาการจากคู่มือแอร์ AR70H และตู้เย็นสมมติ 1 รายการเพื่อทดสอบการแยกกลุ่ม

- **ใครเรียกใช้**: Vitest ; **เรียกใช้**: `./symptoms`, type `GraphSummary`

## 2. อธิบายทีละบล็อก

### บล็อก A — ข้อมูลทดสอบ (บรรทัด 5–49)
`acGraph(overrides)` สร้าง `GraphSummary` ค่าเริ่มต้นเป็นแอร์ Samsung `AR70H**D1***` ; ค่าจริง 4 รายการ: `TIMER`, `BLINKING`, `STOPS_WORKING`, `NOT_COLD` (ชื่อไทยตรงกับไฟล์ข้อมูล) และ `FRIDGE` (Refrigerator, รุ่น `TEST-FRIDGE`, ใช้เฉพาะในเทสจัดกลุ่ม)

### บล็อก B — เทส (5 เทส)
| บรรทัด | สิ่งที่ยืนยัน |
|---|---|
| 52 | `symptomName` ใช้ชื่อไทยถ้ามี |
| 56 | ไม่มีชื่อไทย → ถอยไปชื่ออังกฤษ |
| 63 | เรียงอาการในกลุ่มตามพจนานุกรมไทย — ลำดับที่คาด: `TIMER`(ตั้งเวลา), `BLINKING`(ไฟกะพริบ), `STOPS_WORKING`(แอร์ไม่ทำงาน), `NOT_COLD`(แอร์ไม่เย็น) โดย "แอร์..." เรียงตาม อ ซึ่งอยู่ท้ายสุด |
| 76 | แยกเครื่องคนละประเภทเป็นคนละกลุ่ม (2 กลุ่ม) หาด้วย `find` เพราะไม่ได้กำหนดลำดับกลุ่ม |
| 91 | ไม่แก้ลำดับของ array ที่ส่งเข้ามา |

## 3. การส่งข้อมูล

Vitest เรียกฟังก์ชันล้วนโดยตรง ไม่มี DOM

## 4. จุดที่ควรระวัง

- เทสลำดับไทยพึ่ง `Intl.Collator('th')` ของ runtime ที่รันเทส (Node ต้องมี ICU ที่รองรับภาษาไทย) — ถ้าไม่รองรับเทสอาจล้ม (อนุมานจากพฤติกรรมของ Intl)
- ข้อมูลตู้เย็นเป็นค่าสมมติ ไม่ได้มาจากข้อมูลจริง (ตามคอมเมนต์ในไฟล์)
