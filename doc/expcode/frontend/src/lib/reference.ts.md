# frontend/src/lib/reference.ts

## 1. หน้าที่ของไฟล์

สร้างข้อความ "ที่มาของขั้นตอน" (เลขหน้าและชื่อคู่มือ) จาก `NodeReference` ที่ทุกสถานะแนบมา ค่านี้มาจากข้อมูลผังขั้นตอน (ระดับกราฟ) ไม่ได้ให้ LLM สร้าง หน้าจอแค่จัดรูปแบบ ไม่แต่งเนื้อหาเพิ่ม

- **ใครเรียกใช้**: `components/step/ReferenceLine.tsx`, `pages/HomePage.tsx`, `reference.test.ts`
- **เรียกใช้**: type `NodeReference` จาก `../api/types`

## 2. อธิบายทีละบล็อก

- `EN_DASH = '–'` (12): ขีดยาว U+2013 ใช้คั่นช่วงตัวเลข ไม่ใช่ hyphen
- `formatPages([first, last])` (19–23): หน้าเดียว → `หน้า 43` ; หลายหน้า → `หน้า 43–44`
- `formatSourceLine(reference, manualLabel?)` (35–38): คืน `ที่มาของขั้นตอนนี้: <คู่มือ …|รหัสเอกสาร> <หน้า>` — ถ้าส่ง `manualLabel` (เช่น `Samsung AR70H**D1***`) ใช้ `คู่มือ <label>` ไม่เช่นนั้นถอยไปใช้ `reference.source` เพื่อไม่ให้บรรทัดนี้ว่าง ; ใช้คำว่า "ที่มาของขั้นตอนนี้" ไม่ใช่ "อ้างอิง" เฉยๆ ไม่ให้เข้าใจผิดว่าทุกข้อความในกล่องมาจากคู่มือ (คำเตือนความปลอดภัยบางข้อผู้พัฒนาเขียนเอง)

## 3. การส่งข้อมูล

`RenderedNode.reference {source, pageRange}` (จาก engine ฝั่ง backend) → `formatSourceLine` → ข้อความที่ `ReferenceLine` แสดง

## 4. จุดที่ควรระวัง

- ข้อความ "ที่มาของขั้นตอนนี้" ครอบคลุมทั้งโหนดที่มาจากคู่มือและโหนดที่ผู้พัฒนาเพิ่มเอง (เช่นคำเตือนความปลอดภัย) เพราะข้อมูลของโหนดไม่ได้แยกความต่างนี้ — คอมเมนต์ในไฟล์ยอมรับข้อจำกัดนี้
- `manualLabel` ต้องประกอบเองจากรายการอาการ (`GraphSummary`) โดยหน้าที่เรียก
