# frontend/.env.development

> หมายเหตุ: สรุปนี้แสดง **เฉพาะชื่อตัวแปรและคอมเมนต์** ไม่ได้เปิดดูหรือคัดลอกค่าของตัวแปร

## 1. หน้าที่ของไฟล์

ตัวแปรสภาพแวดล้อมที่ Vite โหลดเฉพาะตอนรัน `npm run dev` (โหมด development) ระบุที่อยู่ backend ที่หน้าเว็บเรียก และสวิตช์ว่าจะใช้เซิร์ฟเวอร์จำลองในเบราว์เซอร์หรือไม่ ไฟล์นี้ commit ขึ้น git ได้เพราะไม่มีความลับ (คอมเมนต์ 2–3: ห้ามใส่ API key ใดๆ เพราะค่าที่ขึ้นต้นด้วย `VITE_` จะถูกฝังลงไฟล์ JS ที่ผู้ใช้เปิดดูได้)

- **ใครเรียกใช้**: Vite (โหลดอัตโนมัติ) ; โค้ดอ่านผ่าน `import.meta.env.VITE_*` ใน `frontend/src/api/http.ts`, `frontend/src/api/traversal.ts` และ `frontend/src/api/queries.ts` (ตามหน้าที่ของไฟล์เหล่านั้น) ; ชนิดของตัวแปรประกาศใน `frontend/src/env.d.ts`
- **เรียกใช้**: ไม่มี

## 2. อธิบายทีละบล็อก

| บรรทัด | ตัวแปร | ความหมายตามคอมเมนต์ |
|---|---|---|
| 6 | `VITE_API_URL` | ที่อยู่ของ backend ในเครื่องตัวเอง — **ห้ามใส่ `/` ท้ายบรรทัด** |
| 10 | `VITE_USE_MOCK` | `true` = ใช้เซิร์ฟเวอร์จำลองในเบราว์เซอร์ ไม่ต้องเปิด backend ; `false` = เรียก backend จริงตาม `VITE_API_URL` |

## 3. การส่งข้อมูล

```
.env.development ─Vite─► import.meta.env.VITE_API_URL / VITE_USE_MOCK ─► ชั้น API ของ frontend เลือกว่าจะเรียก fetch ไป backend หรือเรียก mockServer
```

## 4. จุดที่ควรระวัง

- ค่าที่ขึ้นต้นด้วย `VITE_` เป็นข้อมูลสาธารณะ (อยู่ในบันเดิลที่ส่งให้เบราว์เซอร์) ห้ามใส่ความลับ
- ค่า `VITE_USE_MOCK` ถูกอ่านเป็นสตริง ต้องเทียบกับ `'true'` ในโค้ด (อนุมานจากธรรมชาติของ `import.meta.env`)
- เปลี่ยนค่าแล้วต้องรีสตาร์ต `npm run dev` จึงมีผล (พฤติกรรมมาตรฐานของ Vite)
