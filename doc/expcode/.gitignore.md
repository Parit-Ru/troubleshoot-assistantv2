# .gitignore (รากโปรเจกต์)

## 1. หน้าที่ของไฟล์

บอก git ว่าไฟล์/โฟลเดอร์ไหนทั่วทั้ง repo ไม่ต้องติดตามหรือ commit

- **ใครเรียกใช้**: git (ไม่ใช่โค้ดโปรแกรม)
- **เรียกใช้**: ไม่มี

## 2. อธิบายทีละบล็อก

| บรรทัด | รายการ | ความหมาย |
|---|---|---|
| 1–3 | `node_modules/`, `dist/`, `build/` | แพ็กเกจที่ติดตั้งและผลลัพธ์การ build |
| 5–6 | `.env`, `.env.local` | ตัวแปรสภาพแวดล้อมที่มีความลับ |
| 8–9 | `.DS_Store`, `*.log` | ไฟล์ระบบ macOS และ log |
| 11–14 | `.venv/`, `venv/`, `env/` | สภาพแวดล้อมเสมือนของ Python |
| 16–18 | `__pycache__/`, `*.py[cod]` | cache ของ Python |
| 20 | `repository-backup.git/` | โฟลเดอร์สำรอง repo (bare) ในโฟลเดอร์เดียวกัน |

## 3. การส่งข้อมูล

ไม่มี — มีผลเฉพาะตอน `git add` / `git status`

## 4. จุดที่ควรระวัง

- รายการนี้ **ไม่ได้ ignore ไฟล์ `.env.development` / `.env.production`** ของ frontend ซึ่งถูกติดตามใน git (ตามรายการไฟล์ที่ git ติดตามอยู่) ; ค่าในไฟล์เหล่านั้นไม่ได้ถูกเปิดอ่านในการสรุปนี้
- `backend/.gitignore` และ `frontend/.gitignore` มีกฎเสริมของตัวเอง (เช่น `model-cache/`)
- `dist/` และ `build/` ถูก ignore ทุกระดับ — โค้ดใดที่ต้องการให้ commit ในชื่อโฟลเดอร์เหล่านี้จะถูกข้าม
- ไม่มี `coverage/` และ `doc/` ใน ignore: โฟลเดอร์ `doc/expcode/` ที่สร้างใหม่จะปรากฏเป็นไฟล์ยังไม่ติดตามใน `git status`
