# backend/src/symptom-search/symptom-matcher.spec.ts

## 1. หน้าที่ของไฟล์

ไฟล์ทดสอบ (Jest) ของ `symptom-matcher.ts` ทดสอบฟังก์ชันล้วน 4 ตัว: `cosineSimilarity`, `buildSymptomTexts`, `rankGraphs`, `selectMatches` โดยใช้เวกเตอร์ปลอมที่คำนวณด้วยมือได้ ไม่โหลดโมเดล ไม่ต่อ MySQL ยกเว้นเคสเดียวที่อ่านไฟล์ผังแอร์จริงเพื่อยืนยันว่าข้อความตัวแทนครบ (คอมเมนต์ 6–7)

- **ใครเรียกใช้**: ถูกรันโดย Jest (ดู `jest.config.js`) ไม่มีไฟล์อื่น import
- **เรียกใช้**: `./symptom-matcher`, `fs`, `path`, และไฟล์ข้อมูล `data/manuals/samsung_ac_ar70h.json` (อ่านจริงในเทสเดียว)

## 2. อธิบายทีละบล็อก

### บล็อก A — import และตัวช่วย (บรรทัด 10–36)
- `src(graph_id, entry_symptom, entry_symptom_th?, entry_symptom_aliases?)` (24–31): สร้างผังจำลองที่มีเฉพาะ field ที่ matcher ใช้
- `row(graphId, text, vector)` (34–36): สร้างแถวดัชนีเวกเตอร์ปลอม

### บล็อก C — `describe('buildSymptomTexts')` (บรรทัด 72–122) — 5 เทส

- 85: ข้ามข้อความว่าง / ช่องว่างล้วน / field ที่ไม่มี
- 92: trim ช่องว่างหน้าหลัง
- 97: ผูกทุกข้อความกับ `graphId` ของผังตัวเอง

### บล็อก D — `describe('rankGraphs')` (บรรทัด 124–164) — 4 เทส

### บล็อก E — `describe('selectMatches')` (บรรทัด 166–186) — 3 เทส

## 4. จุดที่ควรระวัง

- **เทสบรรทัด 109 เปราะต่อข้อมูล**: ฝังตัวเลข 13 ผัง / 36 ข้อความตายตัว ถ้าเพิ่ม/ลบผังหรือคำพ้องในไฟล์คู่มือแอร์ เทสนี้จะล้มโดยไม่ใช่บั๊กของโค้ด (อนุมานจากโค้ด)
- path `'../../../data/manuals/…'` นับจาก `backend/src/symptom-search/` ขึ้นสามระดับไปที่ราก repo — ใช้ได้เมื่อรันจากตำแหน่งโค้ดนี้เท่านั้น
- ไม่มีเทสกรณีเวกเตอร์ที่ไม่ normalize ใน `rankGraphs` แต่ `cosineSimilarity` คำนวณ norm เองจึงครอบคลุมในระดับฟังก์ชันย่อยแล้ว (อนุมานจากโค้ด)
