# backend/.gitignore

## 1. หน้าที่ของไฟล์

บอก git ว่าไฟล์/โฟลเดอร์ไหนใน `backend/` ไม่ต้องติดตามหรือ commit

- **ใครเรียกใช้**: git (ไม่ใช่โค้ดโปรแกรม)
- **เรียกใช้**: ไม่มี

## 2. อธิบายทีละบล็อก

| บรรทัด | รายการ | ความหมาย |
|---|---|---|
| 1 | `node_modules/` | แพ็กเกจที่ติดตั้ง |
| 2–3 | `dist/`, `build/` | ผลลัพธ์จากการ build |
| 5–6 | `.env`, `.env.local` | ไฟล์ตัวแปรสภาพแวดล้อม (มีความลับ เช่นรหัสผ่าน DB) |
| 8–9 | `__pycache__/`, `*.pyc` | cache ของ Python |
| 11 | `.DS_Store` | ไฟล์ระบบของ macOS |
| 12 | `*.log` | ไฟล์ log |
| 14 | `model-cache/` | โฟลเดอร์ cache ของโมเดลที่ดาวน์โหลด (ต่างจาก `model-slim/` ที่เก็บใน git) |

## 3. การส่งข้อมูล

ไม่มี — มีผลเฉพาะตอน `git add`/`git status`

## 4. จุดที่ควรระวัง

- `model-slim/` **ไม่ถูก ignore** (ตั้งใจให้อยู่ใน repo ตามคอมเมนต์ใน `embedding.service.ts`) ขณะที่ `model-cache/` ถูก ignore
- ไม่มี `coverage/` ในรายการ ทั้งที่ `jest.config.js` เขียนรายงาน coverage ไปที่ `backend/coverage` (ตาม `coverageDirectory: '../coverage'`) — ถ้ารัน coverage ไฟล์รายงานอาจถูกติดตามโดย git (อนุมานจากโค้ด)
- `.env.example` ไม่ถูก ignore ถูกต้องตามจุดประสงค์ (เป็นแม่แบบที่ commit ได้)
