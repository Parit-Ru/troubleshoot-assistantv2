# backend/.env.example

> หมายเหตุ: สรุปนี้แสดง **เฉพาะชื่อตัวแปรและคอมเมนต์** ไม่ได้เปิดดูหรือคัดลอกค่าในไฟล์ใดๆ ตามกติกา (ไฟล์ `backend/.env` จริงไม่ได้ถูกเปิดอ่าน)

## 1. หน้าที่ของไฟล์

แม่แบบของไฟล์ `backend/.env` ที่ผู้พัฒนาคัดลอกแล้วกรอกค่าจริง ระบุตัวแปรสภาพแวดล้อมทั้งหมดที่ backend อ่าน (คอมเมนต์บรรทัด 2–3: คัดลอกเป็น `backend/.env`; ห้าม commit ไฟล์ `.env` เพราะ `.gitignore` กันไว้)

- **ใครเรียกใช้**: คนติดตั้งระบบ (คัดลอกด้วยมือ); `database.module.ts` มีข้อความ error ที่ชี้มาที่ไฟล์นี้ เมื่อขาดตัวแปรบังคับ
- **ใครอ่านค่าตัวแปร**: `main.ts` (`dotenv/config`, `CORS_ORIGIN`, `PORT`), `database.module.ts` (`DB_*`), `symptom-search.service.ts` (`SYMPTOM_SEARCH_ENABLED`), `health.controller.ts` (`NODE_ENV`), และสคริปต์ใน `backend/scripts/` (`dotenv/config` + `DB_*`)

## 2. อธิบายทีละบล็อก

### บล็อก A — ฐานข้อมูล (บรรทัด 5–16)
| บรรทัด | ตัวแปร | บังคับ? | ใช้ที่ไหน |
|---|---|---|---|
| 8 | `DB_HOST` | บังคับ | `buildPoolOptions()` ใน `database.module.ts` |
| 9 | `DB_PORT` | บังคับ | แปลงเป็น `Number` |
| 10 | `DB_USER` | บังคับ | |
| 11 | `DB_PASSWORD` | ไม่บังคับ (ถ้าไม่มีใช้ `''`) | |
| 12 | `DB_NAME` | บังคับ | |
| 16 | `DB_SSL_CA` | ไม่บังคับ | เนื้อไฟล์ CA ตอนต่อ MySQL แบบ TLS (คอมเมนต์ 14–15: เว้นว่างตอนใช้ MySQL ในเครื่อง; ตอน deploy วางเนื้อหา `ca.pem`) |

### บล็อก B — เซิร์ฟเวอร์ (บรรทัด 18–23)
`PORT`, `NODE_ENV`, `CORS_ORIGIN` (อ่านใน `main.ts` และ `health.controller.ts`)

### บล็อก C — ค้นหาอาการ (บรรทัด 25–35)
- `SYMPTOM_SEARCH_ENABLED` (31): ต้องเป็น `true` เป๊ะๆ จึงโหลดโมเดล ค่าอื่นหรือเว้นว่าง = ปิด; ปิดอยู่เซิร์ฟเวอร์ส่วนอื่นทำงานปกติ ผู้ใช้เลือกอาการจากรายการได้; ใช้ RAM ราว 250–300 MB; ดูสถานะที่ `GET /symptom-search/status`
- คอมเมนต์ 33–35: ตอน deploy บน Linux (เช่น Render) ให้ตั้ง `ONNXRUNTIME_NODE_INSTALL=skip` ที่ขั้นติดตั้งแพ็กเกจ (ไม่ใช่ใน `.env`) เพื่อไม่ให้ `onnxruntime-node` ดาวน์โหลดไลบรารี CUDA ที่ CPU ไม่ใช้

### บล็อก D — LLM (บรรทัด 37–41)
`GEMINI_API_KEY`, `GROQ_API_KEY` — คอมเมนต์ระบุว่า "ยังไม่ได้ใช้ (ชั้นเรียบเรียงถ้อยคำ ยังไม่ได้ทำ)"

## 3. การส่งข้อมูล

```
.env (คัดลอกจากไฟล์นี้) ─dotenv/config─► process.env ─► database.module / main / symptom-search.service / scripts/*.js
```

## 4. จุดที่ควรระวัง

- **ไม่พบการอ่าน `GEMINI_API_KEY` / `GROQ_API_KEY` ในโค้ด backend `src/`** (ตรงกับคอมเมนต์ว่ายังไม่ได้ใช้) — เป็นตัวแปรที่เตรียมไว้
- ตัวแปร `DB_SSL_CA` เป็นข้อความหลายบรรทัด (PEM) ต้องระวังเรื่องการขึ้นบรรทัดในแพลตฟอร์ม deploy — โค้ด `normalizePem` แปลง `\n` ให้เอง
- ไฟล์นี้เป็นแม่แบบเท่านั้น: ค่าจริง (รหัสผ่านฐานข้อมูล, API key) ต้องอยู่ใน `.env` ที่ถูก ignore
