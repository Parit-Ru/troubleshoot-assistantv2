# ขั้น 2 — ให้ engine รันในเบราว์เซอร์ได้

แก้ไฟล์เดียวคือ `backend/src/traversal-engine/traversal-engine.ts` จำนวน 2 จุด ทั้งคู่อยู่ต้นไฟล์

เป็นการแตะไฟล์ใน backend ครั้งเดียวของงานฝั่งหน้าจอทั้งหมด จึงแยกเป็น commit ของตัวเอง เพื่อให้ย้อนกลับได้โดยไม่กระทบงานอื่น

---

## 1. ทำไมถึงต้องแก้

เราต้องการเซิร์ฟเวอร์จำลองที่รันในเบราว์เซอร์ เพื่อสร้างหน้าจอทั้งหมดในขั้น 3 ถึง 9 โดยยังไม่ต้องมี backend

คำถามคือเซิร์ฟเวอร์จำลองนั้นจะรู้ได้อย่างไรว่าขั้นถัดไปคืออะไร

| ทางเลือก | ผล |
|---|---|
| เขียนตรรกะเดินกราฟขึ้นมาใหม่ในฝั่งหน้าจอ | มีตรรกะสองชุดที่ต้องดูแลให้ตรงกัน ถ้าเพี้ยนจากกันเมื่อไหร่ หน้าจอจะโกหกเรื่องด่านความปลอดภัย |
| ใช้ไฟล์ engine ตัวเดียวกับเซิร์ฟเวอร์ | มีตรรกะชุดเดียวเหมือนเดิม แต่ต้องแก้ 2 จุดที่ผูกกับ Node |

เลือกทางที่สอง เพราะหลักการของโครงงานคือกราฟเป็นผู้ตัดสิน ถ้าหน้าจอมีตรรกะเดินกราฟของตัวเอง หลักการนี้จะถูกละเมิดตั้งแต่ในโค้ด

---

## 2. แก้อะไรบ้าง

### จุดที่ 1 แยก `import` เป็น `import type`

ของ 14 อย่างที่ import จาก `types.ts` มี 9 อย่างเป็น type ล้วน ซึ่งหายไปตอน compile และอีก 5 อย่างเป็น class ของ error ที่มีตัวตนจริงตอนรัน

เดิมเขียนรวมกันใน `import` เดียว ซึ่ง backend ยอมรับ แต่ tsconfig ของ frontend ตั้ง `verbatimModuleSyntax` ไว้ ซึ่งบังคับให้แยกสองกลุ่มนี้

ถ้าไม่แยก จะได้ error `TS1484` จำนวน 9 ตัวทันทีที่ frontend อ้างถึงไฟล์นี้

### จุดที่ 2 เปลี่ยนวิธีสร้าง UUID

| เดิม | ใหม่ |
|---|---|
| `randomUUID()` จาก `node:crypto` | `globalThis.crypto.randomUUID()` |

`node:crypto` เป็นโมดูลของ Node ที่เบราว์เซอร์ไม่มี Vite จึงตัดทิ้งตอน build พร้อมขึ้นคำเตือนว่า externalized for browser compatibility ซึ่งแปลว่าโค้ดนั้นจะพังตอนรันจริง

`globalThis.crypto.randomUUID()` เป็นมาตรฐานเว็บที่ Node ตั้งแต่เวอร์ชัน 20 มีให้เหมือนกัน โปรเจกต์นี้ใช้ Node 22 จึงใช้ได้ทั้งสองฝั่ง เป็นฟังก์ชันเดียวกัน ให้ค่าแบบเดียวกัน

## 3. ทำไมพฤติกรรมไม่เปลี่ยน

ทั้งสองจุดไม่แตะตรรกะการเดินกราฟ

`resolveNextNode` ซึ่งเป็นจุดเดียวในระบบที่ตัดสินใจว่าขั้นถัดไปคืออะไร และเป็นจุดที่บังคับด่านความปลอดภัย ไม่ถูกแก้แม้แต่ตัวอักษรเดียว

หลักฐาน

| ตรวจอะไร | ผล |
|---|---|
| `npm test` ฝั่ง backend | 82 passed เท่าเดิม |
| `tsc` ฝั่ง backend | ผ่าน |
| `tsc -b` ฝั่ง frontend ที่อ้างถึงไฟล์นี้ | ผ่าน จากเดิมที่ได้ error 10 ตัว |
| `vite build` | ไม่มีคำเตือนเรื่อง `node:crypto` อีก |

## 4. ข้อควรระวัง

`crypto.randomUUID` ใช้ได้เฉพาะเมื่อหน้าเว็บอยู่บน `localhost` หรือ `https` เท่านั้น เป็นข้อกำหนดด้านความปลอดภัยของเบราว์เซอร์เอง ไม่ใช่ข้อจำกัดของโค้ด

ผลคือถ้าเปิด dev server จากโทรศัพท์ผ่านเลข IP ในวง LAN เช่น `http://192.168.1.5:5173` โหมดจำลองจะพัง เพราะสร้าง sessionId ไม่ได้

ข้อจำกัดนี้อยู่เฉพาะโหมดจำลอง เว็บจริงบน GitHub Pages เป็น https อยู่แล้ว และ sessionId ก็สร้างจากฝั่งเซิร์ฟเวอร์ ไม่ใช่จากเบราว์เซอร์

วิธีทดสอบบนโทรศัพท์จริงอยู่ในขั้น 10.4 คือทดสอบกับเว็บที่ deploy แล้ว

## 5. คำถามที่กรรมการอาจถาม

**"engine รันในเบราว์เซอร์ได้แล้ว แปลว่าหน้าจอเดินกราฟเองหรือเปล่า"**

> ไม่ครับ เว็บที่ใช้งานจริงเรียก API อย่างเดียว engine ในเบราว์เซอร์มีเฉพาะในโหมดจำลองตอนพัฒนา และถูกตัดออกจาก build จริงทั้งหมด เพราะโค้ดส่วนนั้นถูกโหลดแบบมีเงื่อนไขจากค่า `VITE_USE_MOCK` ซึ่งเป็น `false` ตอน build ตรวจได้จากโฟลเดอร์ `dist` ที่ไม่มีไฟล์ mock เลย จะพิสูจน์ให้ดูในขั้น 9.3

**"ถ้าอย่างนั้นผู้ใช้แก้โค้ดในเบราว์เซอร์ให้ข้ามด่านได้ไหม"**

> ไม่ได้ครับ ต่อให้แก้โค้ดหน้าเว็บทั้งหมด คำสั่งที่ส่งไปก็ยังต้องผ่าน `resolveNextNode` ที่เซิร์ฟเวอร์ ซึ่งจะตอบ 400 กลับมาและไม่ขยับสถานะ พิสูจน์ได้จากแผงสาธิตในหน้าตรวจอาการ

**"ทำไม engine ถึงย้ายมารันในเบราว์เซอร์ได้ง่ายขนาดนี้"**

> เพราะออกแบบไว้ตั้งแต่แรกว่า engine ห้าม import NestJS ครับ เป็นฟังก์ชันบริสุทธิ์ที่รับกราฟกับสถานะเข้าไปแล้วคืนสถานะใหม่ออกมา ไม่รู้จักฐานข้อมูล ไม่รู้จัก HTTP หลักเดียวกันนี้ทำให้ตอนย้ายจาก PostgreSQL ไป MySQL ก็ไม่ต้องแตะ engine เลย
