# ขั้น 1 — ตั้งค่าพื้นฐาน

ขั้นนี้ยังไม่มีหน้าจอใหม่ เป็นการวางรากฐานให้ขั้นต่อไปเขียนโค้ดได้โดยไม่ต้องตัดสินใจเรื่องสีหรือขนาดซ้ำอีก

| ไฟล์ | ทำอะไร |
|---|---|
| `tailwind.config.js` | นิยามสีและฟอนต์ของโปรเจกต์ |
| `src/index.css` | เรียก Tailwind และตั้งสีพื้นของหน้า |
| `index.html` | ภาษา ชื่อแท็บ และค่าสำหรับมือถือ |
| `.env.development` | ค่าตอนพัฒนา |
| `.env.production` | ค่าตอน deploy |

---

## 1. `tailwind.config.js`

### ทำไมใช้ `theme.extend` ไม่ใช่ `theme`

ถ้าเขียนใน `theme` ตรงๆ สีมาตรฐานของ Tailwind จะหายทั้งชุด ตอนนี้ `src/components/Layout.tsx` และ `src/pages/Home.tsx` ยังใช้ `bg-gray-900` กับ `text-yellow-400` อยู่ สองไฟล์นั้นจะถูกลบในขั้น 4.12 ระหว่างนี้ต้องให้ใช้งานได้ต่อไป

### ทำไมตั้งชื่อสีตามหน้าที่

ใช้ `canvas` `panel` `danger` แทนชื่อเฉดสีอย่าง `slate-950` เพราะชื่อตามหน้าที่บอกว่าใช้ตอนไหน และถ้าวันหนึ่งเปลี่ยนเฉดสี ชื่อจะยังถูกอยู่

| ชื่อ | ค่า | ใช้กับ |
|---|---|---|
| `canvas` | `#0B0F1A` | พื้นหลังหน้า และสีตัวอักษรบนปุ่มส้ม |
| `panel` | `#0E1422` | กล่องขั้นตอน แผงด้านข้าง |
| `line` | `#1E293B` | เส้นขอบ เส้นทางขั้นตอน |
| `accent` | `#F59E0B` | ปุ่มไปต่อ เมนูที่เลือก หน้าส่งต่อช่าง |
| `ink` | `#F1F5F9` | ข้อความหลัก |
| `ink-soft` | `#94A3B8` | ข้อความรอง |
| `ink-faint` | `#64748B` | ชื่ออังกฤษ บรรทัดที่มา |
| `success` | `#4ADE80` | หน้าจบแบบ `user_fixed` |
| `info` | `#60A5FA` | หน้าจบแบบ `normal_behavior` แถบโหมดจำลอง |
| `danger` | `#F87171` | คำเตือนความปลอดภัย ข้อผิดพลาด |

ค่าทั้งหมดวัดจากพิกเซลของไฟล์ Figma จริง ยกเว้นสองจุดที่ตั้งใจแก้

1. ข้อความรองใน Figma เป็น `#5A5E6A` ซึ่งคอนทราสต์ 2.96:1 ต่ำกว่าเกณฑ์ WCAG ที่ 4.5:1 เปลี่ยนเป็น `#94A3B8` ได้ 7.46:1
2. กล่องคำเตือนใน Figma เป็นสีส้ม เปลี่ยนเป็นสีแดง เพื่อสงวนสีส้มไว้เป็นสีของการกระทำอย่างเดียว

### กฎที่ต้องจำ

ตัวอักษรบนปุ่มสีส้มต้องเป็น `text-canvas` ซึ่งได้คอนทราสต์ 8.9:1 ห้ามใช้ `text-white` ที่ได้แค่ 2.15:1

### `DEFAULT` ใน `ink`

คีย์ `DEFAULT` ทำให้เขียน `text-ink` สั้นๆ ได้ ส่วนคีย์อื่นต่อท้ายชื่อเป็น `text-ink-soft` และ `text-ink-faint`

### ไม่ต้องสร้างสีจางแยก

Tailwind ใส่ความโปร่งใสให้สีที่เป็น hex ได้เอง กล่องคำเตือนจึงใช้ `bg-danger/10 border-danger/40` ได้เลย ไม่ต้องประกาศสีจางเพิ่มใน config

## 2. `src/index.css`

### ทำไมไม่ต้องเขียน `font-sans` ทุกที่

ชั้น base ของ Tailwind นำ `fontFamily.sans` จาก config ไปใส่ให้ `html` เอง ทุกข้อความจึงได้ฟอนต์นี้อัตโนมัติ

### ทำไมใช้ฟอนต์ที่ติดมากับเครื่อง

ตอนแรกวางแผนใช้ IBM Plex Sans Thai Looped ผ่าน Fontsource แต่ตัดสินใจไม่ใช้ เพื่อลด dependency และไม่ต้องแบกไฟล์ฟอนต์ประมาณ 127 KB

ผลที่ยอมรับคือหน้าตาตัวอักษรจะต่างกันไปตามเครื่อง ลำดับใน config จึงไล่ตามระบบปฏิบัติการ คือ Windows ได้ Leelawadee UI, Android ได้ Noto Sans Thai, iOS และ macOS ได้ Thonburi

ถ้าภายหลังอยากกลับไปใช้ฟอนต์ฝัง แก้แค่สองไฟล์คือ `tailwind.config.js` กับ `index.css` ไม่กระทบไฟล์อื่นเลย

### ทำไมตั้งสีพื้นที่ `body` ไม่ใช่ `#root`

ถ้าตั้งที่ `#root` แล้วเนื้อหาสั้นกว่าความสูงจอ ส่วนที่เหลือด้านล่างจะเป็นสีขาว และตอนดึงหน้าเกินขอบบนมือถือจะเห็นแถบขาวแวบขึ้นมา

### `@layer base` คืออะไร

บอก Tailwind ว่ากฎนี้เป็นค่าเริ่มต้นของ element ไม่ใช่ utility class ผลคือถ้ามีคลาสอย่าง `bg-panel` มาทับที่ element เดียวกัน คลาสจะชนะเสมอ โดยไม่ต้องพึ่งลำดับการเขียน

## 3. `index.html`

| สิ่งที่เปลี่ยน | เหตุผล |
|---|---|
| `lang="en"` เป็น `lang="th"` | ภาษาไทยไม่มีช่องว่างระหว่างคำ เบราว์เซอร์ต้องรู้ภาษาจึงจะตัดคำขึ้นบรรทัดใหม่ได้ถูกตำแหน่ง และโปรแกรมอ่านหน้าจอจะออกเสียงถูกภาษา |
| `<title>` | เดิมเป็นคำว่า frontend ซึ่งจะโผล่บนแท็บตอนสาธิต |
| `theme-color` | สีแถบบนของเบราว์เซอร์บนมือถือ ให้กลืนกับพื้นหลัง |
| `color-scheme: dark` | บอกเบราว์เซอร์ว่าเป็นธีมมืด แถบเลื่อนและช่องกรอกจะเปลี่ยนเป็นโทนมืดตาม ไม่งั้นช่องกรอกรหัสข้อผิดพลาดจะเป็นกล่องขาวโดดกลางหน้าจอมืด |
| `description` | ข้อความที่ขึ้นตอนแชร์ลิงก์ |

### สิ่งที่ตั้งใจไม่แก้

บรรทัด favicon เขียนว่า `/favicon.svg` ดูเหมือนจะพังบน GitHub Pages ที่อยู่ใต้ path ย่อย แต่ Vite เติม path ให้เองตอน build กลายเป็น `/troubleshoot-assistantv2/favicon.svg` ตรวจแล้วจากไฟล์ `dist/index.html`

ส่วน `viewport` ไม่ใส่ `maximum-scale` หรือ `user-scalable=no` เพราะจะทำให้ผู้ใช้ซูมไม่ได้

## 4. ไฟล์ `.env`

### Vite ใช้ไฟล์ไหนเมื่อไหร่

| คำสั่ง | ไฟล์ที่อ่าน |
|---|---|
| `npm run dev` | `.env.development` |
| `npm run build` และ `npm run deploy` | `.env.production` |

### ทำไมต้อง commit ขึ้น git

ไฟล์ทั้งสองไม่มีความลับ มีแค่ที่อยู่เซิร์ฟเวอร์กับสวิตช์เปิดปิดโหมดจำลอง ถ้าไม่ commit คนที่ clone repo ไปจะรันไม่ได้ทันที เพราะโค้ดจะโยน error ว่าไม่มี `VITE_API_URL`

`.gitignore` ที่โฟลเดอร์รากกันเฉพาะ `.env` กับ `.env.local` ซึ่งไม่ครอบคลุมสองไฟล์นี้ ถูกต้องตามที่ต้องการแล้ว

### ทำไมต้องขึ้นต้นด้วย `VITE_`

Vite ส่งเฉพาะตัวแปรที่ขึ้นต้นด้วยคำนี้เข้าโค้ดฝั่งเบราว์เซอร์ ตัวแปรชื่ออื่นถูกกันไว้ เป็นกลไกกันเผลอเอาความลับใส่

ผลที่ตามมาคือห้ามใส่ API key ในไฟล์เหล่านี้เด็ดขาด เพราะค่าจะถูกฝังลงไฟล์ JS ที่ใครก็เปิดดูได้

### `VITE_USE_MOCK` มีไว้ทำไม

ระหว่างขั้น 3 ถึง 9 เราสร้างหน้าจอทั้งหมดโดยยังไม่ต้องมี backend ค่านี้เป็น `true` ตอนพัฒนา และเป็น `false` เสมอตอน deploy เพราะเว็บจริงห้ามใช้เซิร์ฟเวอร์จำลอง ซึ่งไม่มีการบังคับด่านความปลอดภัยฝั่งเซิร์ฟเวอร์

ค่านี้ยังทำให้ Vite ตัดโค้ด mock และไฟล์กราฟทั้งหมดออกจาก build ด้วย จะตรวจจริงในขั้น 9.3

### ข้อควรระวัง

Vite อ่านไฟล์ `.env` ตอนเริ่มเซิร์ฟเวอร์เท่านั้น แก้ระหว่างที่ dev server รันอยู่จะไม่มีผล ต้องกด Ctrl+C แล้วรัน `npm run dev` ใหม่

### ที่ยังค้างอยู่

`VITE_API_URL` ใน `.env.production` ต้องเป็น URL จริงของ backend บน Render และต้องเป็น `https` ไม่ใช่ `http` เพราะ GitHub Pages เสิร์ฟผ่าน https ถ้าเรียก http เบราว์เซอร์จะบล็อกทิ้งและขึ้น error ว่า Mixed Content

ทั้งสองไฟล์ห้ามมี `/` ท้าย URL เพราะโค้ดใน `http.ts` จะต่อ path ที่ขึ้นต้นด้วย `/` อยู่แล้ว

## 5. ของที่ลบออก

| สิ่งที่ลบ | เหตุผล |
|---|---|
| แพ็กเกจ `zustand` | ติดตั้งไว้แต่ไม่เคย import ที่ไหน โครงงานนี้ไม่มี state ส่วนกลาง |
| `src/App.css` | มาจาก template ของ Vite เป็นสไตล์ของหน้าตัวอย่าง ไม่มีใคร import |
| `src/assets/` | มาจาก template ของ Vite ทั้งโฟลเดอร์ |

ตรวจก่อนลบด้วยการค้นทั้ง `src/` และ `index.html` แล้วไม่พบการอ้างถึงเลย

### ทำไมไม่เก็บ zustand ไว้เผื่อ

ไม่ใช่เรื่องขนาดไฟล์ แต่เป็นเรื่องการสอบ ถ้ากรรมการเปิด `package.json` แล้วถามว่าใช้ทำอะไร คำตอบว่าไม่ได้ใช้ครับ จะดูแย่กว่าการไม่มีมันตั้งแต่แรก

state ในโครงงานนี้อยู่ 4 ที่ คือแคชของ React Query สำหรับข้อมูลจากเซิร์ฟเวอร์, URL สำหรับ sessionId, `useState` ของ component สำหรับช่องติ๊กและค่าที่กรอก, และ `useState` ของหน้าตรวจอาการสำหรับเส้นทางขั้นตอน ไม่มีอันไหนต้องใช้ร่วมกันทั้งแอป

### สิ่งที่ห้ามลบ

`frontend/public/favicon.svg` ยังถูกอ้างถึงใน `index.html` โฟลเดอร์ `public/` คนละอันกับ `src/assets/`

## 6. ตรวจว่าขั้น 1 เสร็จจริง

1. `npm run dev` เปิดได้ พื้นหลังเป็นสีกรมท่าเข้ม ตัวอักษรไทยอ่านได้ปกติ
2. แท็บเบราว์เซอร์แสดงชื่อ FixBot ผู้ช่วยตรวจอาการเครื่องใช้ไฟฟ้า
3. แถบเลื่อนด้านขวาเป็นโทนมืด
4. `npm run build` ผ่าน
5. ใน `package.json` ส่วน `dependencies` เหลือ 4 ตัว คือ `@tanstack/react-query`, `react`, `react-dom`, `react-router-dom`

## 7. ต่างจากแผนตรงไหน

แผนเดิมในขั้น 1.2 ระบุให้ติดตั้งฟอนต์ผ่าน Fontsource ภายหลังตัดสินใจใช้ฟอนต์ที่ติดมากับเครื่องแทน จำนวนขั้นย่อยยังเท่าเดิม แต่ขั้น 1.2 ไม่มีคำสั่ง `npm install` แล้ว
