ข้อจำกัดของการทดสอบนี้ (ต้องบอกตรงๆ)
======================================================================
1. session ที่ใช้ทดสอบหน้าเว็บ สร้างผ่าน API แล้วเปิดหน้า #/session/<id> ในเว็บจริง ไม่ได้คลิกผ่านหน้าเลือกอาการ
2. เบราว์เซอร์ที่ใช้คือ Chrome headless หน้าจอเดสก์ท็อป 1000x900 เท่านั้น ไม่ได้ลอง Safari/iOS และไม่ได้ฟังด้วยโปรแกรมอ่านหน้าจอ
   การจัดวางบนมือถือ (375px) เคยตรวจแล้วกับ dev server และเซิร์ฟเวอร์ปลอม ไม่ได้รันซ้ำบนเว็บจริง (bundle เป็นไฟล์เดียวกัน)
3. ไม่ได้ทดสอบ: กรณี SESSION_NOT_FOUND ในฟอร์ม, การรอนานตอน Render ตื่น (ระบบอุ่นอยู่ตอนทดสอบ /health ตอบ 0.6 วินาที)
4. ส่งพร้อมกัน 10 คำขอจากเครื่องเดียวไปยัง Render หนึ่งตัว ได้ผู้ชนะ 1 คนและ 409 อีก 9 คนในการรันนี้ เป็นหลักฐานว่า UPDATE
   ที่มีเงื่อนไข "outcome_text IS NULL" ทำงานแบบ atomic ในรอบนี้ แต่ไม่ใช่การพิสูจน์ทุกลำดับการแทรกของคำขอ
5. เงื่อนไขของแต่ละข้อ (ค่าที่คาดหวัง) ผู้ช่วยเขียนเองจากโค้ดของ controller/service/filter จึงยืนยันว่าระบบจริง "ตรงกับที่โค้ดบอก"
   ไม่ใช่การเทียบกับสัญญาที่อาจารย์ที่ปรึกษากำหนดแยกต่างหาก
6. ข้อมูลที่ทดสอบเป็นของปลอมที่ผู้ช่วยแต่ง (ไทย อีโมจิ HTML ข้อความ 1,000 ตัวอักษร) ไม่ใช่ข้อมูลของผู้ใช้จริง
