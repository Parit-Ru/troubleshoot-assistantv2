3) ความผิดพลาดของสคริปต์ที่แก้ระหว่างทดสอบ (บันทึกตามจริง)
======================================================================
การรันกับ Render ครั้งที่ 1 และ 2 (session 07392f6c-95fc-47cd-8b52-c3a3b220d6c0 และ
939ac569-0446-41b6-8a8b-107fbf05449b) ข้อ 4 ไม่ผ่าน: ได้ HTTP 400 แต่ code ว่าง
ฐานข้อมูลของทั้งสอง session ยังมี 3 แถวและไม่มีแถว continue (ด่านทำงานถูก)

สาเหตุที่ตรวจพบ: ไม่ใช่เซิร์ฟเวอร์ ตรวจด้วยไคลเอนต์อีกตัว (node fetch) ซ้ำสถานการณ์เดียวกันกับ Render
ได้ body ครบ:
  {"statusCode":400,"code":"SAFETY_CONFIRMATION_REQUIRED","message":"โหนด 'n_fix_breaker' เป็น safety_critical ต้องส่ง action 'confirm_safety' เท่านั้น จะใช้ 'continue' เฉยๆ ไม่ได้"}
(ข้อความ error เหมือนกับในเครื่องทุกตัวอักษร ผ่าน Cloudflare) ส่วน Windows PowerShell 5.1 อ่าน
$_.ErrorDetails.Message ของคำตอบ error จาก Render ได้ค่าว่าง
การแก้: ให้สคริปต์อ่าน body จากสตรีมของคำตอบ (GetResponseStream) ก่อน แล้วค่อยถอยไปใช้ ErrorDetails.Message
หลังแก้ ผ่านทั้งในเครื่องและกับ Render
(ข้อจำกัด: ไม่ได้พิสูจน์ว่าทำไม ErrorDetails.Message ว่างเฉพาะกับ Render รู้แค่ว่าอ่านจากสตรีมแล้วได้)

5) สิ่งที่หลักฐานนี้พิสูจน์ และสิ่งที่ไม่ได้พิสูจน์
======================================================================
พิสูจน์: ด่านความปลอดภัยที่สถานะ n_fix_breaker (safety_critical) ถูกบังคับที่เซิร์ฟเวอร์
 - ส่ง continue โดยตรงไปที่ REST API (ไม่ผ่านหน้าเว็บ) ถูกปฏิเสธ 400 SAFETY_CONFIRMATION_REQUIRED
 - สถานะไม่ขยับ และฐานข้อมูลไม่มีแถวของ action ที่ถูกปฏิเสธ
 - ยืนยันคำเตือน (confirm_safety) ผ่านได้ ด่านจึงไม่ใช่การบล็อกทุกอย่าง
 - ผลเหมือนกันทั้ง backend ในเครื่องและ Render
ไม่ได้พิสูจน์:
 - ด่านของสถานะ safety_critical ตัวอื่น (n_power_off, n_power_back_on ฯลฯ) ทดสอบเฉพาะ n_fix_breaker ของผัง stops_working
 - ข้อ 3 ของ T2 (เปิดหน้าเว็บ ใส่ ?demo=1 กดปุ่มสาธิต และอัดวิดีโอ) เป็นงานของผู้ใช้ ยังไม่ได้ทำ
 - PowerShell 7 (pwsh) ไม่มีในเครื่อง จึงทดสอบเฉพาะ Windows PowerShell 5.1
 - ไม่ได้ทดสอบการส่ง action ในขณะที่ระบบค้นหากำลังโหลด
