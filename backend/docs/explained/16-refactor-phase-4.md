# Refactor เฟส 4 — แยกส่วนหน้าตาออกจาก `SessionView` และเปลี่ยนชื่อ `ErrorNotice` ที่ชนกัน

(เฟส 3 ถูกรวมเข้าเฟสนี้ตามที่ตกลง) หน้าจอทำงานเหมือนเดิมทุกอย่าง

## เปลี่ยนอะไร

**1. แยก 3 ส่วนหน้าตาออกจาก `SessionPage.tsx` เป็นไฟล์ใหม่ใน `frontend/src/components/`**
ทุกตัวรับ props อย่างเดียว ไม่มี state ไม่มี hook ใหม่ ไม่เรียก API คัดลอก JSX เดิมมาทั้งก้อนไม่ปรับอะไร

| ไฟล์ | ประโยคเดียวที่อธิบายได้ |
|---|---|
| `SessionHeader.tsx` | แสดงชื่ออาการ รุ่นเครื่อง ปุ่ม "ยกเลิกการตรวจ" และบรรทัดคะแนนความคล้าย |
| `TerminalActions.tsx` | ปุ่มสองปุ่มท้ายหน้าจบ: "ตรวจอาการอื่น" กับ "เริ่มอาการนี้ใหม่" |
| `SessionErrorNotice.tsx` | กล่องข้อผิดพลาดของหน้าตรวจอาการ พร้อมปุ่มทางออกตาม `recovery` (ย้ายมาทั้งก้อนจาก `ErrorNotice` เดิมในไฟล์เดียวกัน) |

**2. เปลี่ยนชื่อ `ErrorNotice` ที่ชนกัน 2 หน้า (ทำคนละอย่าง)**
`SessionPage` → `SessionErrorNotice` (ไฟล์ข้างบน) · `SymptomsPage` → `SymptomsErrorNotice` (ยังอยู่ในไฟล์เดิม เปลี่ยนชื่อ 4 จุด: นิยาม 1 + เรียกใช้ 3) `SearchErrorNotice` ไม่ถูกแตะ

**3. สิ่งที่ตั้งใจ "ไม่ย้าย"**
state, effect, ตัวกันกดเบิ้ล และฟังก์ชันจัดการการกดทั้งหมดอยู่ใน `SessionView` ต่อ เพราะต้องเรียกตามลำดับเดิมก่อน `return` ก่อนเวลา การย้ายต้องใช้ custom hook ซึ่งกฎของงานนี้ห้าม ผลคือ `SessionView` สั้นลงไม่มาก

## ตรวจว่าหน้าจอไม่เปลี่ยนอย่างไร
โปรเจกต์ไม่มี jsdom จึงไม่มีเทสของ component ผมจึงเก็บ **HTML ของ `#root` ใน 21 สถานะ** ด้วย Chrome จริงก่อนแก้ แล้วเก็บชุดเดียวกันหลังแก้ แล้วเทียบทีละไฟล์ (เซิร์ฟเวอร์ปลอมในเบราว์เซอร์ ไม่แตะเซิร์ฟเวอร์จริง ไม่เขียนฐานข้อมูล)
- หน้าตรวจอาการ: กำลังโหลด, ระหว่างตรวจ (มี/ไม่มีคะแนนความคล้าย), จบแบบ resolution (มี/ไม่มีคะแนน), จบแบบ escalation, บันทึกผลแล้ว, ไม่มีรายการอาการ (หัวข้อชั่วคราว), error ตอนโหลด 3 แบบ (ไม่พบ/เครือข่าย/ข้อมูลผังเสียที่โชว์รหัส), error ตอนตอบ 3 แบบ (ไม่ตรงกับเซิร์ฟเวอร์/ข้ามด่านความปลอดภัย/เครือข่าย), error ตอน "เริ่มอาการนี้ใหม่", error ตอนบันทึกผล
- หน้าเลือกอาการ: ปกติ, โหลดรายการล้ม 2 แบบ, เริ่ม session ล้ม 2 แบบ
- **ผล: เหมือนกันทุกตัวอักษร 21/21 ไฟล์** และก่อนใช้เป็นหลักฐาน ผมเก็บชุดอ้างอิงซ้ำสองรอบกับโค้ดเดิมได้เหมือนกัน 21/21 (พิสูจน์ว่าตัวเก็บนิ่ง ไม่ได้ต่างกันเพราะความสุ่ม)
- ตัวตรวจ Chrome เดิม 63 ข้อ ผ่าน 63/63 · vitest 8 ไฟล์ 84 ข้อ ผ่าน · `tsc -b`, `eslint src`, `vite build` ผ่าน · bundle จริงไม่มีของ mock · ไฟล์ test ไม่ถูกแตะ (hash ตรง)

## ที่ไม่ได้ตรวจ
- สถานะที่ต้องรอเวลา (กล่อง "เซิร์ฟเวอร์กำลังเริ่มทำงาน" เมื่อรอเกิน 4 วินาที) และสถานะ "กำลังยกเลิก" (ปุ่มหมุน) ไม่ได้อยู่ใน 21 สถานะ โค้ดสองส่วนนี้ไม่ได้ถูกย้าย (`slowNotice` อยู่ใน `SessionView`) แต่ปุ่มยกเลิกที่หมุนอยู่ย้ายไปอยู่ใน `SessionHeader` และมีผ่านแค่ `isLoading` ที่ส่งต่อไปตรงๆ
- ไม่ได้ลองบนเบราว์เซอร์อื่นนอกจาก Chrome
