# ขั้น 1.2.3 — เทียบโมเดลเดิมกับโมเดลที่ตัดแล้ว

## 1. ทำอะไร และทำไม

ขั้น 1.2.2 ตัดตารางคำศัพท์แล้ว และสคริปต์ Python ตรวจว่าแถวที่ป้อนเข้าโมเดลเหมือนเดิมทุกไบต์ แต่ยังไม่เคยรันโมเดลที่ตัดแล้วจริง ขั้นนี้รันทั้งสองตัวด้วย **transformers.js ตัวเดียวกับที่เซิร์ฟเวอร์จะใช้** แล้วเทียบเวกเตอร์ที่ได้ทีละข้อความ

ในขั้นตอนเดียวกัน สคริปต์รายงาน peak RSS ของโมเดลที่ตัดแล้วด้วย จึงได้ตัวเลขหน่วยความจำที่ต้องตัดสินใจไปพร้อมกัน (ขั้น 1.2.4 ที่วางแผนไว้จึงรวมอยู่ในขั้นนี้)

## 2. สคริปต์ทำงานอย่างไร

1. โปรเซสหลักเรียกตัวเองซ้ำ 2 ครั้ง ครั้งละ 1 โมเดล (`original` แล้ว `slim`) โปรเซสแยกกัน เพราะ peak RSS นับตลอดอายุโปรเซส ถ้ารวมกันจะวัดปนกัน (เหตุผลเดียวกับ `measure-memory-options.js`)
2. แต่ละโปรเซสลูกตั้ง `env.cacheDir` ชี้ไปโฟลเดอร์ของโมเดลตัวเอง และ `allowRemoteModels = false` เพื่อการันตีว่าใช้ไฟล์ในเครื่องเท่านั้น ห้ามแอบดาวน์โหลด แล้วแปลงข้อความชุดเดียวกัน เขียนเวกเตอร์ลงไฟล์ชั่วคราว
3. โปรเซสหลักอ่านผลทั้งสอง เทียบทีละข้อความ แล้วลบไฟล์ชั่วคราว

ข้อความที่ใช้เทียบ 141 ข้อความ: ข้อความตัวแทนของ 13 ผัง (36) + ข้อความในสถานะทุกตัว (98) + คำค้นตัวอย่าง (7)

## 3. วิธีรัน

ยืนที่ **`backend/`**

```powershell
node scripts/compare-models.js
```

ต้องมีทั้ง `backend/model-cache/` (ขั้น 1.1) และ `backend/model-slim/` (ขั้น 1.2.2) ใช้เวลาไม่กี่นาที เพราะไม่ต้องดาวน์โหลดอะไร

## 4. วิธีอ่านผล

| ตัวเลข | ความหมาย | เกณฑ์ |
|---|---|---|
| จำนวนมิติ | ต้องเป็น 384 | ไม่ใช่ = โหลดผิดโมเดล |
| เหมือนกันทุกบิต | จำนวนข้อความที่เวกเตอร์เท่ากันทุกตัวเลข | คาดว่า 141 จาก 141 |
| cosine ต่ำสุด | ข้อความที่แย่ที่สุดยังคล้ายกันแค่ไหน | ผ่านถ้า ≥ 0.99999 |
| ความต่างสูงสุดรายมิติ | ต่างกันมากสุดกี่หน่วยในมิติใดมิติหนึ่ง | คาดว่า 0 |
| **peak RSS ของ slim** | ตัวชี้ขาดเรื่องหน่วยความจำ | ≤ 350 ผ่าน · 350–450 เสี่ยง · > 450 ไม่ผ่าน |

สคริปต์จบด้วย exit code 0 เมื่อผ่านและ 1 เมื่อไม่ผ่าน

## 5. ข้อจำกัด

- **ผลทดสอบของผู้ช่วยใช้โมเดลจำลอง 16 มิติเท่านั้น** ผ่านด้วย transformers.js และ ONNX Runtime ตัวจริง ได้เหมือนกันทุกบิต 141 จาก 141 และเมื่อทดสอบกับโมเดลที่ตัดผิดโดยตั้งใจ สคริปต์รายงานไม่เหมือนเลย (cosine ต่ำสุด 0.776) ตัวเลขหน่วยความจำจากโมเดลจำลองไม่มีความหมาย การรันกับโมเดลจริงบนเครื่องคุณเป็นครั้งแรก
- peak RSS นี้ไม่รวม NestJS และ MySQL driver ที่เซิร์ฟเวอร์จริงใช้เพิ่ม และวัดบน Windows ส่วน Render เป็น Linux (ตอนวัดไลบรารีเปล่าๆ ในเครื่องทดสอบ Linux ใช้ราว 100 MB เทียบกับ 50 MB บน Windows ของคุณ) จึงต้องเผื่อเกณฑ์ไว้
- ผ่านการเทียบเวกเตอร์ ไม่ได้แปลว่าผลค้นหาถูกต้องขึ้น แปลว่าเท่าเดิมเท่านั้น (กรณี "กดรีโมท…" ที่จับผิดผังยังต้องแก้ในขั้นตั้งเกณฑ์)

## 6. ขั้นต่อไปขึ้นกับผล

- **เวกเตอร์ไม่เหมือน:** หยุด ห้ามใช้ `model-slim/` ส่งผลมาให้ผมตรวจ
- **เหมือนกัน และ peak RSS ≤ 350 MB:** เดินแผน A ต่อ ขั้น 1.2.5 หาที่เก็บไฟล์ ~53 MiB ให้ Render ดาวน์โหลดตอน build
- **เหมือนกัน แต่ peak RSS ยังเกิน:** ตัดคำศัพท์ได้ผลไม่พอ ต้องคุยทางเลือกอื่นที่ไม่มีค่าใช้จ่าย
