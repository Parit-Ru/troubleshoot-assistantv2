# Refactor เฟส 1 — จัดคอมเมนต์และถอด export ที่ไม่มีใครใช้

เป้าหมายของงาน refactor ทั้งชุดคือให้เจ้าของโปรเจกต์อธิบายโค้ดทุกบรรทัดให้อาจารย์ฟังได้เอง โดย **พฤติกรรมของระบบเหมือนเดิมทุกอย่าง** เฟสนี้แตะเฉพาะคอมเมนต์กับคำว่า `export` ไม่แตะตรรกะใดๆ

## เปลี่ยนอะไร

**1. ตัดการอ้างขั้นตอนภายในออกจากคอมเมนต์ให้หมด** เช่น "ตามตารางข้อ 4 ของ HANDOFF", "(A.5)", "(ขั้น 1.8)", "ตัดสินใจแล้วในข้อ B8", "(D7)", "ต้องรอขั้น 10.2" ข้อความเหล่านี้อ้างถึงเอกสารงานภายในที่อาจารย์ไม่เห็น และเจ้าของโปรเจกต์อธิบายต่อไม่ได้ ที่ยังต้องการสื่อ (เช่น เหตุผลที่ session อายุ 24 ชั่วโมง) ผมเขียนเป็นเหตุผลตรงๆ แทน (ตรวจซ้ำด้วยการค้นแล้วไม่เหลือ ยกเว้น `D1` ในเลขรุ่นแอร์ AR70H ซึ่งไม่ใช่การอ้างขั้นตอน)

**2. แก้คอมเมนต์ที่ล้าสมัยหรือผิด**
- `traversal.service.ts` พูดถึง "เทส 43 ข้อฝั่งหน้าจอ" (ปัจจุบัน 84) และ `DemoPanel` พูดถึง "รอ REST API" ทั้งที่ REST API มีแล้ว
- `session.store.ts` เลิกอ้างว่า "ตัดสินใจแล้วในข้อ B8" และระบุตรงๆ ว่าอายุ session ใช้ค่า `SESSION_TTL_HOURS = 24` ในไฟล์นี้ (คอมเมนต์ใน migration 002 ที่เขียนว่า 2 ชั่วโมงแก้ไม่ได้ตามกฎ จึงบันทึกไว้ว่าค่าจริงคือค่าในโค้ด) และตัดประโยคคาดการณ์ถึงหน้า Analytics ในอนาคตออก เพราะเป็นของนอกขอบเขต

**3. เหลือคอมเมนต์ที่บอก "ทำไม"** ใน 3 ไฟล์ที่คอมเมนต์เยอะที่สุด ตัดประโยคที่เล่าซ้ำสิ่งที่โค้ดบอกอยู่แล้ว และย่อส่วนหัวที่ยาว:

| ไฟล์ | บรรทัดคอมเมนต์ ก่อน → หลัง |
|---|---|
| `traversal/session.store.ts` | 118 → 89 |
| `traversal/traversal.service.ts` | 112 → 91 |
| `traversal/traversal.exception.filter.ts` | 46 → 38 |

**4. ถอด `export` ที่ไม่มีไฟล์ไหนใช้ (7 ตัว)** เหลือเป็นของภายในไฟล์
`MODEL_CACHE_DIR`, `MAX_RESULTS`, `GraphDataIntegrityError`, `MAX_INPUT_LENGTH` (backend) · `ButtonVariant`, `NoticeTone`, `StartSessionVariables` (frontend)
หลักที่ใช้: ถ้าชนิดปรากฏอยู่ในลายเซ็นของฟังก์ชันที่ export ออกไป (เช่น `SearchBody`, `StartSessionBody`) **คง `export` ไว้** เพราะ backend เปิด `declaration: true` และชนิดนั้นเป็นส่วนของรูปร่างสาธารณะของฟังก์ชันอยู่แล้ว

## ก่อน/หลังต่างกันอย่างไร
ตัวอย่าง `traversal.exception.filter.ts` ส่วนหัวก่อนมี 26 บรรทัด อ้าง "HANDOFF", "A.1", "A.5", "A.7" และนับ "11 ชนิด" ตอนนี้เหลือ 19 บรรทัด บอกว่า filter ทำอะไร ทำไมใช้ `instanceof` ทำไมแยก `toErrorBody()` และข้อจำกัดเรื่อง JSON ผิดไวยากรณ์ ซึ่งเป็นสิ่งที่อาจารย์อาจถาม

## ตรวจว่าพฤติกรรมไม่เปลี่ยนอย่างไร
- **โค้ดจริงเหมือนเดิม:** ให้ TypeScript พิมพ์ไฟล์ทั้ง 23 ไฟล์ที่แก้ออกมาจาก AST แบบตัดคอมเมนต์ แล้วเทียบกับ `HEAD` ทีละบรรทัด ต่างกันเฉพาะคำว่า `export` ที่ถอด 7 จุด (สคริปต์ตรวจอยู่นอก repo)
- **test:** backend 10 ชุด 183 ข้อ ผ่าน · frontend 8 ไฟล์ 84 ข้อ ผ่าน (เท่าค่าตั้งต้น) · ไฟล์ test ไม่ถูกแตะ (เทียบ hash ตรง)
- `tsc` ของ backend ทั้งแบบ dev และแบบ build (เปิด declaration), `tsc -b` กับ `eslint` กับ `vite build` ของ frontend ผ่านหมด

## ที่ไม่ได้ทำในเฟสนี้ (ตั้งใจ)
- ไม่ได้ไล่ตัดคอมเมนต์ "ประเภทเล่าซ้ำโค้ด" ครบทุกไฟล์ ทำใน 3 ไฟล์ backend ที่คอมเมนต์หนาแน่นที่สุด (ส่วน `graph.repository.ts` แก้แค่จุดอ้างอิงภายใน จำนวนบรรทัดคอมเมนต์เท่าเดิม) ไฟล์อื่นที่ยังมีคอมเมนต์ยาวแต่บอกเหตุผล (เช่น `traversal-engine.ts`, `SessionPage.tsx`) คงไว้
- ไม่ลบ `/gallery`, `DemoPanel` (รอเฟสถัดไปตามที่ตัดสินใจ), ไม่แก้ test, ไม่แตะ `backend/scripts/` และ `scripts/` (Python)
