# ขั้น 1.3 — `symptom-matcher.ts` ตรรกะจับคู่อาการ

งานค้นหาอาการด้วยภาษาธรรมชาติต้องตอบคำถามเดียวว่า **"คำที่ผู้ใช้พิมพ์ คล้ายกับอาการของผังขั้นตอนไหนมากที่สุด"** ขั้นนี้เขียนส่วนที่ตอบคำถามนั้นโดยเฉพาะ และแยกออกจากส่วนที่แปลงข้อความเป็นเวกเตอร์ (ขั้น 1.4) ไฟล์นี้จึงไม่รู้จักโมเดล ฐานข้อมูล หรือ NestJS เลย รับเวกเตอร์เข้ามาแล้วคำนวณล้วนๆ

| ไฟล์ | หน้าที่ |
|---|---|
| `src/symptom-search/symptom-matcher.ts` | ฟังก์ชันล้วน 4 ตัว: `cosineSimilarity`, `buildSymptomTexts`, `rankGraphs`, `selectMatches` |
| `src/symptom-search/symptom-matcher.spec.ts` | เทส 19 เคส |

> **ศัพท์:** เอกสารนี้ใช้คำว่า เครื่องสถานะ / สถานะ ตาม PROJECT_CONTEXT ข้อ 3
> ชื่อในโค้ดยังคงเดิม: **`graph` ในโค้ด = ผังขั้นตอนการวินิจฉัย 1 อาการ (เครื่องสถานะ 1 ชุด)**
> เช่น `rankGraphs` = จัดอันดับผังขั้นตอน, `graph_id` = รหัสผังขั้นตอน

## 2. ฟังก์ชัน 4 ตัว

### 2.1 `cosineSimilarity(a, b)`

$$\cos(a,b) = \frac{a \cdot b}{|a|\,|b|}$$

วัด **มุม** ระหว่างเวกเตอร์สองตัว ไม่ใช่ความยาว ผลอยู่ระหว่าง -1 ถึง 1

| กรณี | ผล | เหตุผล |
|---|---|---|
| ทิศเดียวกัน | 1 | ความหมายตรงกัน |
| ตั้งฉาก | 0 | ไม่เกี่ยวกัน |
| ทิศตรงข้าม | -1 | |
| มิติไม่เท่ากัน | **โยน error** | แปลว่าเวกเตอร์มาจากโมเดลคนละตัว เทียบกันไม่ได้ ควรพังให้เห็นชัด ไม่ใช่ให้ตัวเลขมั่ว |
| เวกเตอร์ศูนย์ | 0 | กันหารด้วยศูนย์ (ไม่ให้ได้ NaN) |

เวกเตอร์จากโมเดลถูก normalize แล้ว (`normalize: true`) สูตรนี้จึงเท่ากับ dot product เฉยๆ แต่ยังหารความยาวไว้เพื่อให้ฟังก์ชันถูกต้องกับเวกเตอร์ทุกแบบ

### 2.2 `buildSymptomTexts(graphs)`

สร้างรายการ "ข้อความตัวแทนของอาการ" ของแต่ละผัง ลำดับ **ไทย → อังกฤษ → คำพ้อง** จาก field ที่มีอยู่แล้วเท่านั้น:

| field | ความหมาย |
|---|---|
| `entry_symptom_th` | ชื่ออาการภาษาไทย |
| `entry_symptom` | ชื่ออาการภาษาอังกฤษ |
| `entry_symptom_aliases` | คำพ้อง/วิธีเรียกอื่น |

ข้อความว่างหรือมีแต่ช่องว่างถูกข้าม ข้อความถูกตัดช่องว่างหน้าหลัง **ไม่แต่งประโยคเพิ่มเอง** ผังแอร์จริง 13 ชุดได้ 36 ข้อความ (มีเทสยืนยัน)

> **สิ่งที่พบตอนดูโค้ด:** `GraphRepository.listAll()` คืนแค่ `GraphSummary` ซึ่งไม่มีคำพ้อง
> ตอนสร้างดัชนี service (ขั้น 1.6) จึงต้องเอา id จาก `listAll()` แล้วเรียก `findById()` เพื่อได้ผังเต็ม
> ฟังก์ชันนี้จึงรับชื่อ field แบบ snake_case ตาม `TroubleshootingGraph`

### 2.3 `rankGraphs(queryVector, index)`

- ดัชนี = ข้อความตัวแทนทุกข้อความ พร้อมเวกเตอร์ของแต่ละข้อความ
- **คะแนนของผัง = cosine สูงสุดในบรรดาข้อความของผังนั้น** (ผังมีหลายข้อความ ขอให้ข้อความใดข้อความหนึ่งใกล้คำค้นก็พอ)
- คืน **1 แถวต่อผัง** พร้อม `matchedText` บอกว่าข้อความไหนทำให้ได้คะแนนนั้น
- เรียงมากไปน้อย ถ้าคะแนนเท่ากันเรียงตาม `graphId` เพื่อให้ผลซ้ำได้ทุกครั้ง (ตรงกับหลักของโครงงานที่ต้องการผลลัพธ์ซ้ำได้)

### 2.4 `selectMatches(ranked, threshold, max)`

เอาเฉพาะแถวที่ `score >= threshold` แล้วตัดไม่เกิน `max` รายการ

- คะแนนเท่าเกณฑ์พอดี **ผ่าน**
- ไม่มีผังผ่านเกณฑ์ → คืนรายการว่าง ผู้เรียกต้องนำไปสู่ **การส่งต่อศูนย์บริการ Samsung ห้ามเดา**

## 3. ตัวอย่างการทำงาน (เวกเตอร์ 2 มิติที่คิดด้วยมือได้)

คำค้น = `[1, 0]`

| ผัง | ข้อความ | เวกเตอร์ | cosine |
|---|---|---|---|
| g1 | ข้อความ a | `[0, 1]` | 0 |
| g1 | ข้อความ b | `[1, 0]` | 1 |
| g2 | ข้อความ c | `[1, 1]` | 0.707 |

ผลจัดอันดับ: g1 (1.0, จาก "ข้อความ b") แล้ว g2 (0.707) — g1 ใช้คะแนนสูงสุดของสองข้อความ ไม่ใช่ค่าเฉลี่ย

## 4. ข้อควรระวังทางวิชาการ

| เรื่อง | ต้องทำ |
|---|---|
| cosine **ไม่ใช่ความน่าจะเป็น** | แสดงเป็น "คะแนนความคล้าย 0.72" ห้ามเขียน "มั่นใจ 72%" |
| เกณฑ์ตัด (`MATCH_THRESHOLD` กำหนดในขั้น 1.6 เป็น 0.5 ชั่วคราว) | ขั้น 1.9.4 เปลี่ยนเป็น 0.55 จากชุดตั้งเกณฑ์ที่ AI ร่าง ยังไม่ผ่านชุดรายงานผล **ห้ามอ้างเป็นความแม่นยำ** ดูเอกสาร 11 |
| ผลลัพธ์ของขั้นนี้ | เป็นการทดสอบตรรกะด้วยเวกเตอร์ปลอม ไม่ใช่ผลวัดความแม่นยำของการค้นหา |
| โมเดล embedding | เป็นโมเดลสำเร็จรูป ไม่ได้เทรนเอง หน้าที่คือเลือกว่า **จะเริ่มผังไหน** และผู้ใช้ต้องยืนยันเอง ไม่ได้ตัดสินขั้นใดภายในผัง |

## 5. เทส (19 เคส)

| กลุ่ม | เคส | สิ่งที่พิสูจน์ |
|---|---:|---|
| `cosineSimilarity` | 7 | ค่า 1 / 0 / -1, ไม่ขึ้นกับความยาว, ค่าที่คิดมือ 1/√2, มิติไม่เท่ากัน, เวกเตอร์ศูนย์ |
| `buildSymptomTexts` | 5 | ลำดับ, ข้ามข้อความว่าง, ตัดช่องว่าง, ผูก `graphId`, ผังแอร์จริง 13 ชุด = 36 ข้อความ |
| `rankGraphs` | 4 | 1 แถวต่อผัง + `matchedText`, เรียงมากไปน้อย, เสมอกันเรียงตาม `graphId`, ดัชนีว่าง |
| `selectMatches` | 3 | คะแนนเท่าเกณฑ์ผ่าน, ไม่เกิน `max`, ไม่มีผังผ่านเกณฑ์ |
